# 兼容清单：博客依赖旧编辑服务的地方

换掉博客里的旧编辑服务之前，新工具必须逐条做到这里写的行为。清单是 2026-10-23 在博客里 grep 出来的（`4580`、`/api/*`、`location.port`、`/编辑器/`、`编辑服务`、`修改单`、`反馈/`、`feedback.js`、`127.0.0.1`、根地址链接），每条都对照过代码。回归脚本 `tests/regression/run.py` 的用例编号写在最后一列；旧服务的实测基线在 `tests/regression/results/`。

- 文件路径都相对 `内容/个人博客/`。「旧服务」指 `99-其他/脚本/编辑服务.py`，下文行号前写 `服务:`。
- 「新工具必须」是硬要求；标了「建议」的是旧服务自己的毛病，新工具最好顺手改掉，回归里只记录、不判对错。

| B 接口和落盘格式 | 8 | `/api/pages`、`/api/sheet`、`/api/save` 的请求与回执、文字写回规则、脱敏撤回、写回格式、修改单文件、`/api/feedback` |
| C 博客专属、要搬进站点配置的 | 6 | 页面登记、editor.js 里写死的名单、主题键、编辑器界面样式、过期的 v3-4b-1 引用、脚本和目录路径 |

合计 24 条兼容点（A 10 + B 8 + C 6），另有 D、E 两组附注。

和审查时已知的线索相比，这次新找到的：

1. **同源存储**（A2）：调整单、文章页调整台、背景格子调色把草稿存在浏览器 localStorage，编辑器和首页共用主题键 `v2-theme`。这些都按「协议 + 主机 + 端口」隔离，新工具换端口或改用 `localhost` 打开，用户以前留的草稿和深浅色偏好就看不到了。
2. **Skill 页也靠根地址跳转**（A4）：`skill-showcase/v9.html:1045-1046` 写的是 `href="/"`、`/#top` 等；另有 `生成文章页.py` 生成的 7 篇文章页全部用 `../../`。
3. **site.js 的数据形状是按编辑器的标签白名单定的**（B4）：`v3-7.html:1428` 注释写明 person.about 只写纯文字，因为编辑器只保留 `<b>`、`<strong>`、`<em>`。
4. **脱敏撤回是「有任何命中就撤回」、扫描跑不起来也算命中**（B5），按输出行判断，不看退出码。
5. **旧服务 Range 的两个毛病**（A7）：`bytes=-100` 被当成 `0-100`；起点超过文件大小时服务端抛 `ValueError`，连接直接断开、没有任何响应。
6. **`/编辑器` 不带斜杠是 404**（A3），没有跳转。
7. **线索修正**：`posts/2026-03-29/index.html:369` 里的 `/api/feedback` 是文章正文里 ASCII 架构图的文字（构建产物 `99-其他/dist/site/posts/2026-03-29/index.html:376` 同理），不是调用方。
