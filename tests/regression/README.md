# 回归脚本

换掉博客的旧编辑服务之前，新工具要在这里和旧服务跑出一样的结果。用例对应的兼容点见 [docs/compat.md](../../docs/compat.md)。

## 怎么跑

在 design-studio 仓库根目录：

```bash
# 旧服务（博客里的 99-其他/脚本/编辑服务.py）
python3 tests/regression/run.py --target old

# 新工具：给启动命令模板
python3 tests/regression/run.py --target new --cmd "{python} -I {repo}/<入口>.py serve {site} --port {port}"
```

命令模板里的占位：

| 占位 | 换成 |
|---|---|
| `{site}` | 沙盒里的博客根目录（相当于 `内容/个人博客/`） |
| `{port}` | 本次分到的空闲端口（从不用 4580） |
| `{python}` | 跑本脚本的 Python |
| `{repo}` | design-studio 仓库根目录 |

模板先按空格拆词再替换占位，路径里有空格也不会拆坏。服务的工作目录是沙盒博客根目录。

常用选项：

| 选项 | 作用 |
|---|---|
| `--only R01,R06,U01` | 只跑这几条。R07 要和 R06 一起跑，R14 要和前面的保存用例一起跑 |
| `--no-ui` | 跳过 UI 冒烟（U 开头） |
| `--keep` | 跑完保留沙盒，打印位置，方便排查 |
| `--blog <目录>` | 真实博客目录，默认 `../../内容/个人博客`（也可以用环境变量 `DS_BLOG`） |
| `--full-media` | 沙盒里视频和图片也照抄（默认换成小的假文件） |
| `--extra <路径>` | 额外带进沙盒的文件或目录（相对博客根目录），可重复 |
| `-v` | 通过的用例也打印证据 |

输出：终端逐条打印 `✓ 通过 / ✗ 失败 / ~ 已知差异 / - 跳过`，不通过的带证据；完整结果写到 `results/<target>-<时间>.json`，每条用例都有证据行。

退出码：

| 码 | 意思 |
|---|---|
| 0 | 全部通过（已知差异和跳过不算失败） |
| 1 | 有用例失败 |
| 2 | 环境问题：沙盒没建成、服务没起来，或者真实博客文件被改了 |

只用 Python 标准库。UI 冒烟要已经装好的 python playwright 和 chromium，没有就跳过并在结果里写明原因。UI 冒烟会掐掉所有外网请求（Google Fonts、CDN），只放行本机。

## 沙盒怎么建

每次运行都新建一个临时目录（`tempfile.mkdtemp`，前缀 `ds-regress-`），跑完删掉。

1. 复制 `4-页面/`：跳过 `_shots/`、`__pycache__/`、`node_modules/`、`.DS_Store`、`*.tmp`；视频、动图、图片换成几十字节的假文件，只有 `4-页面/头像跟随/avatar.mp4` 原样复制，用来测 Range。现在大约 1800 个文件、40 MB。
2. 复制 `0-记录/修改单/`（含 `反馈/`）。
3. 复制 `99-其他/脚本/` 里的 `编辑服务.py`、`脱敏扫描.py`、`脱敏扫描-白名单.txt`。
4. 博客根目录有 `design-studio.json`（新工具的站点配置，暂定名）就一起带进来；其他要带的用 `--extra`。
5. 加沙盒专用的安全夹具：`4-页面/.ds-hidden.txt`、`4-页面/首页/.ds-secret/x.txt`、指向静态根外面的符号链接 `4-页面/_ds-link-out → ../0-记录`。

保护措施：

- 只复制文件内容（`shutil.copyfile`），不建硬链接；每个复制出来的文件都核对一遍 inode 和原件不同。博客里原有的符号链接不带进沙盒。
- 临时目录落在真实博客里面就拒绝继续。
- 开头和结尾各算一次真实博客 `4-页面/首页/首页-v3/data/site.js` 和 `0-记录/修改单/` 下每个文件的 SHA-256，变了就列出文件、退出码 2。注意：如果你跑回归时正开着真编辑服务并保存了东西，这里也会报，看列出来的文件判断是哪种。
- 结果 JSON 里的本机路径换成 `~`、`<博客>`、`<沙盒>`，测试用的手机号和 IP 换成占位符，结果文件可以直接进仓库。

| 编号 | 测什么 |
|---|---|
| R01 | 根地址 302 跳首页，Location 只含 ASCII、解码后等于首页 url |
| R02 | `/编辑器/` 和它引用的 editor.js、editor.css、`/设计规范/tokens.css` |
| R03 | 静态根 = `4-页面/`、目录补 index.html、不缓存、404 |
| R04 | `/api/pages` 有首页及其 url |
| R05 | `/api/sheet?page=首页` 原样返回修改单 |
| R06 | 文字：唯一原句 → 已写入，site.js 字段变新值，其他字段语义不变 |
| R07 | 格式检查：除被改字段外逐字节不变（旧服务记为已知差异；`--target new` 时失败就算失败） |
| R08 | 文字：找不到原句 → 待 AI |
| R09 | 样式 → 待 AI，字段原样记录 |
| R10 | 意见 → 待 AI |
| R11、R12 | 新文字带手机号、IP → 脱敏扫描命中 → 没写入，site.js 回滚 |
| R13 | 一次保存文字 + 样式 + 意见，回执顺序、id 连号 |
| R14 | 修改单只追加，原条目和外层字段不变，id 按天连号 |
| R15 | 未登记页面、未知接口 → 404 |
| R16 | `/api/feedback` 保存、读回、文件位置 |
| R17 | `/api/feedback` 三类真实调用方的请求形状 |
| R18 | `/api/feedback` 名字校验、条目清洗、整份覆盖 |
| R19 | Host 不是本机 → 403 |
| R20 | Origin 不是本机 → 403 |
| R21 | POST 不是 JSON → 415 |
| R22 | 路径穿越（含编码、符号链接）→ 404 |
| R23 | 点开头的文件和目录 → 404 |
| R24 | mp4 Range → 206 + Content-Range |
| R25 | 默认端口 4580：跳过，切换时手动验 |
| U01 | 浏览器：编辑器连上服务、载入首页、修改单条数对得上 |

| U03 | 浏览器：调整单反馈框自动保存到 `反馈/文案审查.json` |

「已知差异」只用在旧服务上：R07 旧服务必然失败（它用 `json.dumps` 重排整份 site.js），记下来但不算失败，新工具要做到精确写回。

## 怎么加用例

在 `run.py` 里找到对应的分组，照着现有用例写一个函数：

```python
@case('R26', '一句话说清测什么')
def t_something(ctx, c):
    r = ctx.get('/api/pages')                      # ctx.get / ctx.post 发请求，自动带本机 Host；POST 自动带 JSON 和本机 Origin
    c.ok(r.status == 200, '200', r.status)        # 每个判断一行：条件、说明、实际值（实际值写进证据）
    c.note('只记录、不判对错的观察')
    # c.skip('原因') 跳过；c.known = '原因' 把失败标成已知差异（只在旧服务上用）
```

- 编号决定顺序和 `--only` 的名字：R 开头是接口用例，U 开头是浏览器用例（拿 `ctx.ui.page`，`ctx.ui.error` 非空就 `c.skip(ctx.ui.error)`）。
- 用例按登记顺序跑，共享同一个沙盒和服务。要改 site.js 字段时用 `ctx.take()` 取一句没用过的唯一原句，别和别的用例改同一个字段；写进修改单的 id 要追加到 `ctx.saved_ids`（`check_saved_record` 会自动加），否则 R14 对不上。
- 只往沙盒写：路径都从 `ctx.site` 拼，读写用 `ctx.read(相对路径)`。
- 测试数据里不要直接写手机号、IP、本机路径（会被博客的脱敏扫描命中）：运行时拼出来，加进 `MASKS` 打码。
- 新工具多了接口（比如以后的 `/api/lab/*`），在 compat.md 加一条兼容点，再在这里加用例，两边编号互相写上。

## 基线

`results/` 里保留一份旧服务的基线（`old-*.json`）。换新工具前，用 `--target new` 跑一遍，和基线逐条对：除 R07 应该从「已知差异」变成「通过」以外，其余结果要一致。其他运行结果按需提交，不提交也行。
